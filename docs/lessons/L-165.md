# L-165 — Skip a check when its subject matches a checked base, not when a mode says so

Found 2026-09-14 by [T-296](../../tasks/T-296-the-readmes-deck-gate-fence-is-what-the-docs-gate-pays-for.md).

The owner chose to skip the README's render-driving block under `check_all.py --docs`. The stated
cost was that a documentation commit could edit the pasted gate output and still pass. That cost
came from the condition, not from the skip. The skip keyed on the mode.

Keyed on the subject, the cost goes away. The block is skipped only while it is identical to its
copy at the base, which a full gate already checked, and while nothing the command reads differs
from the base. Under both conditions the base's verdict is this tree's verdict. A commit that edits
the block runs the check. The pasted lines stand in for the run, so every figure bound to them stays
compared.

**How to apply.** Before accepting that a skip gives up a guarantee, ask what the check reads. If
all of it can be compared with a base that was fully checked, skip on that comparison, and run the
check when it fails. What is still lost is a verdict that changes with no file changing, such as a
browser update. Write that down where the skip is described.
