# L-138 — A run count is evidence about the fix only if it is large against the defect's rate; ten clean runs against a one-in-ten fault is a coin that came up heads

An intermittent defect is measured before it is fixed, or the fix cannot be measured at all. The
rate is not a detail of the report — it decides how many runs a green result has to survive before
it means anything, and that number is usually much larger than the one a session reaches for.

Measured 2026-08-29 on `render.py motion`, closing
[T-272](../../tasks/T-272-render-py-motion-enumerates-a-different-animation-set-across-runs.md). The
tool enumerated a different animation set on the same unchanged deck: **1 run in 10**. Two remedies
were tried.

- Settling the page before taking the animation set: **3 of 22**, no better — and it silently added
  an animation to every report, so it moved the answer while fixing nothing.
- Forcing a style flush after each click: **0 of 10**, which reads as fixed. Ten more runs returned
  **2 of 10**.

At a one-in-ten rate, ten clean runs happen about a third of the time with no change at all. The
first ten proved nothing and looked like proof. Had the second ten not been run, the tool would
have shipped a remedy that does nothing, with a task record stating it was measured.

**Neither remedy shipped.** What shipped is the tool reading the page twice and naming any
animation the two reads disagree on — an instrument that says what it cannot promise, which is
worth more than a number that is stable and wrong.

**How to apply.**

1. **Measure the rate first, and record the full observation rather than its size.** Ten runs
   recording *how many animations* would have said `17, 17, 18, …`; ten recording *which* named the
   offender in one pass and made every later comparison exact.
2. **Ask what a clean run is worth before running it.** At rate *p*, *n* clean runs leave
   `(1-p)^n` — at *p* = 0.1, ten runs leave a third. If that number is not small, the run is not
   evidence and a bigger *n* is the cheapest thing in the task.
3. **A remedy that does not move the rate but does move the answer is worse than the defect.** Check
   both. The settle-first attempt passed a casual look — the numbers still varied by one — and had
   quietly changed what the tool reported.
4. **Where the rate makes proof unaffordable, report the uncertainty instead of claiming
   determinism.** An instrument that reads twice and says where the two reads differ is honest at a
   cost a hand-run tool can pay. This is [L-125](L-125.md)'s discipline pointed at the tool's own
   answer rather than at the check.
5. **This is why an intermittent defect costs more than a wrong one.**
   [T-254](../../tasks/T-254-density-py-write-corrupts-every-self-closing-svg-tag.md) is the same
   shape from the other end: `0, 3, 3` over three runs sent an adopter looking for a race in their
   own deck. A tool that is wrong every time gets fixed; a tool that is wrong sometimes gets
   believed.
