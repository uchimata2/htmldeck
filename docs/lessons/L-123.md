# L-123 — A number read from the DOM is in a coordinate system you have not established, and the error hides wherever the two systems nearly agree

Found 2026-08-19 (**T-178**), building the instrument that renders candidate treatments for the
ruler's dense-mode position mark. Two separate readings were wrong the same way inside one hour, and
neither announced itself.

**The first: a DOM rectangle cannot crop a Chrome capture.** `render.py` screenshots with
`--screenshot`, which captures the *window*, while `getBoundingClientRect` answers in the *viewport*.
The two differ by a constant — a 1920x1234 window lays out at 1898x1080 — so the obvious correction
is an offset, and a centred offset of (11, 77) produced a strip that looked right. It was not right.
At 1120x700 the same model put the crop a whole band too high, and an overlay of three candidate
offsets showed the true one was ~112, matching none of them. The reason the offset model cannot work:
**the layout used for the capture is not the layout `--dump-dom` reports, even in a single
invocation** — at 1120x700 Chrome reported `innerHeight` 546 and painted a frame in which the deck
occupied ~648 px. There is no offset between two things that were laid out differently.

**The second: `getComputedStyle` is measured before the transform and `getBoundingClientRect` after
it.** The deck's stage is scaled by a CSS transform, so inside it a design unit is one CSS pixel
*before* the transform. A probe that divided both reads by the stage scale `k` was correct for one
and wrong for the other — and at the wide window `k` is 0.989, so the error was a rounding
difference and invisible. At the 0.5 hand-over it reported every mark at exactly double: a 7 du dot
as 14, a 14 du section mark as 28. **The numbers stayed internally consistent, which is what made
them believable.** Nothing in the table looked odd; the ratios were all preserved.

**The shape both share.** A measurement carries a coordinate system that is never written down, and
a second system is nearby and nearly equal. Where the two nearly agree — a scale of 0.99, a window
that is almost the viewport — the reading passes every sanity check that exists, including the eye.
The first environment you test in is the one most likely to be forgiving, because it is the roomy
default. So the error is not caught by care; it is caught by testing the *other* end of the range,
and that is a step, not an attitude.

**How to apply.**

1. **Locate the target in the artifact, not in the model of it.** The fix was one throwaway render
   that outlines the wanted box in a colour the themes never use, and one scan that reports where
   that colour landed. The offset then stops being a constant anybody has to keep true, and becomes
   a measurement of the size actually being rendered. `tools/deck/rulerstrip.py`'s `locate()` is the
   worked version.
2. **Take the first reading at the extreme, or take two.** One reading at the roomy default proves
   nothing about the model, only about that point. Both defects here survived a confident reading at
   1920x1234 and died at 1120x700 — which is `chrome_row.py`'s floor size and was already in the
   repository for exactly this reason.
3. **State the space in the code, beside the read.** `du(el)` divides by `k` and `mark(li)` does not,
   and one comment saying why is what stops the next edit from making them consistent and wrong.
4. **A picture that looks plausible is not a checked picture.** The first strip cropped the bottom
   line instead of the ruler and was a well-composed, correctly-sized, entirely wrong image. What
   caught it was looking at the whole frame with the crop rectangle drawn on it — the cheap debug
   render that shows the model and the artifact together.

**What it cost and what it bought.** About an hour, none of it shipped: both were caught before the
treatment was built. What it bought is the reason the acceptance criterion *the rendered size is
stated* is worth having at all — the first version of that number was double, and a task that had
recorded it would have published a measurement no one could reproduce.
