# L-107 — A corruption defect is usually an omission defect too; write the criterion over the whole population

Met 2026-08-16 (**T-171**). `runs()` deleted an inline tag instead of replacing it with a space, so
`<span>If it fails</span><span>Service holds …` reached the figure ledger as `failsService` and was
keyed under `failsservice`. That is what the task was raised about, and the acceptance criterion was
written to match it: *every change is a glued word coming apart, and none is a figure lost*. Two
buckets — **unchanged** and **damaged** — because a defect that corrupts is imagined to corrupt what
it touches and leave the rest alone.

**The measured result had a third bucket, and it was the larger finding.** Across the four decks that
build a ledger, **no figure was lost and six were gained**: one on the reference deck, four on
`sort-window`, one on the seeded fixture. `FIGURE` opens with `(?<![\w.$])`, so a numeral whose
preceding character is a word character is not a figure at all — `gate18%` was never offered for
binding, on either side. The gluing was not only corrupting labels, it was **deleting figures before
the ledger existed**, and those six rows have no *before* to be a change of.

**The criterion had no bucket to file them in.** Both stated outcomes were about rows that already
existed, so a run recovering six figures satisfied the words while the interesting half of the
result went unnamed. Nothing failed — but the criterion would have passed a run that recovered
nothing at all, which is the same sentence doing no work.

**So write it over the population.** Snapshot the whole set, then account for **every member on both
sides**: present-and-same, present-and-changed, absent-after, absent-before. The last one is the
bucket a corruption story never predicts, and it is where the defect's real size usually is. A count
of the set on each side costs one line and is what makes the fourth bucket visible at all.
