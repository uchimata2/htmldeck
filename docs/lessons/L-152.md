# L-152 — A total decays when an item is added and a per-item record does not, so a count nothing binds is deleted, never refreshed

Found 2026-09-01 in [T-234](../../tasks/T-234-the-front-pages-own-figures-and-claims.md), closing
three front-page findings the pre-release audit had ranked, and decided there because B16 had
already measured the alternative. `T-227` corrected the fixture count on the front page; `T-235`,
three commits later in the same batch, added three fixtures and the corrected sentence was wrong
again. `PR-03`'s *two decks* had been wrong for two releases and `PR-124`'s *the sample is one
project* went false the day a second report landed — with every pasted figure on the page correct
and `figures.py` reporting `0 stale`.

- **A total is a claim about the whole set, so every addition to the set falsifies it.** *One
  project*, *two decks*, *sixteen broken fixtures* — each is true on the day it is written and wrong
  the first time somebody adds one of the thing, which is exactly when nobody re-reads the sentence.
  A refreshed total buys the interval until the next addition, and that interval was measured at a
  few commits.
- **A per-item record is falsified by nothing an addition does.** *The first found six defects; the
  second sent twenty-seven records* stays true when a third arrives — the third is a new sentence,
  not a correction. An ordinal per entry is fine; an ordinal standing in for a count is **L-133**.
- **So a count has two honest states, and refreshed is not one of them.** Either a command prints
  it and a check compares it — `figures.py` for a pasted figure, the gate holding
  `examples/README.md` to `DECKS` for the deck list — or it is deleted and the sentence rewritten to
  point at the count's home rather than copy it. The test before writing one: *would adding one more
  of these make this sentence false, and does anything read it when that happens?* Yes and no is
  the case to rewrite.
