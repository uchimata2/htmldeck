# L-114 — A new check inheriting the tool's normalisation can be silent and green at once

A tool that reads text almost always normalises it first — blanking code, stripping front-matter,
folding case. That transformation is invisible once it is a helper everything calls, so a check
added later inherits it without a decision being taken. **If the new rule's evidence is what the
normalisation removes, the check never fires and reports a count of zero**, which reads as a clean
tree rather than as a check that is not running.

The case: `refcheck.py` blanks code spans and fenced blocks, correctly — a link inside code renders
as the characters typed, so nobody can follow it and nothing can break it. A fourth check was added
to compare a link's **label** against its target. But this repository writes the path in a label
inside a code span:

```
[`docs/BRIEF.md`](docs/BRIEF.md)
```

so the labels the check exists to read are exactly the ones the shared helper blanks. Reading the
stripped copy would have compared 711 empty strings, found nothing, and printed *0 disagree* on
every run forever.

*Writing that example cost a round of its own: as prose it is a working link, and check 1 resolved
it from `docs/lessons/` and reported it broken. A fence is the only place this repository can show
link syntax without making one — which is the same boundary check 3 relies on to quote a dead
reference (**L-34**).*

**The split that fixes it is not to stop normalising.** The stripped copy still decides *which links
are followable*; the label is then read where it was written. One transformation answers one
question, and a check that needs a different question asked has to say so.

**How to apply.** When adding a check to an existing text tool, name which copy of the text it reads
and why — the raw one, or the one the helper returns — before writing the rule. Then prove it on a
seeded instance through the **shipped entry point**, not only through the function: a unit assertion
over the comparison passes while the integration is blind, because the blindness lives in what gets
handed to it. This is **L-110**'s shape in a different instrument — the measurement reports zero
rather than failing — and the negative-case rule of **L-103** does not catch it on its own.
