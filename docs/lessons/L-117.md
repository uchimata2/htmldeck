# L-117 — A control that is `display:none` when shut is invisible to every gate, so a green run says nothing about how it looks open

Found 2026-08-18 (**T-114**), on the release that introduced the control. The `More` menu had been
through the whole gate set and passed: `shell.py check` byte for byte, `component.py` against the
contract, `contrast.py` on every colour pair, `audit.py` on the persistence rule, `check.py` on 84
decidable rules. Tab order had been measured through the shipped handlers. Its keyboard state had
been read back off `aria-expanded`.

Rendered open for the first time, it drew a button inside a box: the panel carries a hairline and a
radius, `.btn` carries the same pair, and the item rule overrode only the width and the alignment.
Two concentric rounded rectangles, and three when the keyboard opens the menu and puts the focus
ring inside them.

**The mechanism is one CSS declaration and it defeats measurement completely.** A shut disclosure is
`hidden`, so it computes to `display:none`, so it has no box. Every geometric read returns zero or
nothing, every colour pair inside it is unreachable, and a contract check counts the element without
ever laying it out. **None of those gates failed. None of them could have.** The default state of a
disclosure is the state in which it is unmeasurable, which means the gate suite's coverage of a
disclosure's *appearance* is exactly zero and reads as full.

**How to apply.**

1. **Count a disclosure's open state as unrendered until something has drawn it.** Not measured,
   not asserted, not toggled and read back — drawn, and looked at. `aria-expanded` moving proves
   the handler works, which is a different claim and the one easy to mistake for this one.
2. **When a release adds a component that is shut by default, rendering it open is a release step,
   not a nicety.** It is the only step that reaches it, and no green run will remind you.
3. **The recipe is [L-110](L-110.md)'s** — inject an opener into a throwaway copy and screenshot it
   in real Chrome, re-arming the opener until the target slide is current. Capture the focused *and*
   the unfocused states: `:focus-visible` may not match after a real mouse click, so the picture a
   synthetic click produces is one of the two a person can see, not both.

**What it cost and what it bought.** Nothing shipped wrong, because the look was done before the
tag rather than after. What it bought is the size of the blind spot, which nobody had stated: every
`hidden` panel in this deck — tier two, the provenance box, the quick view, this menu — sits in the
same hole, and the gate suite's silence about all four is indistinguishable from approval.
