# L-91 — After moving text, the defects that survive are the ones no checker binds

Learned 2026-08-14 (**T-146**, **T-147**). Two extractions were done with the strongest mechanical
guarantee available: slice the text, write it elsewhere, and **assert the moved bytes equal the
removed bytes**. Both passed that assertion. Both still shipped broken references, and in both cases
the gates were silent and correct to be silent.

- A markdown link has a target and a **label**. The move rewrote every target; a label still showing
  the old one-level path, beside a target carrying the new two-level one, then passes every check
  while telling the reader a path that is wrong from the new depth. The link works and the words
  beside it lie. *Writing that example with real paths tripped the checker in this very file, which
  is the lesson arriving before the reader does.*
- A section reference is resolved only when a document is named **adjacent** to the mark. A bare
  `(§6.1)` inside the moved text is therefore *unbound* — counted, reported as skipped, and never
  resolved. It kept pointing at the file it had just left.

Neither is a checker defect. Each follows from a rule the checker states: a label is not a pointer,
and adjacency is what binds a mark to a document. **A byte-identity assertion proves the text
survived; it proves nothing about whether the text is still true in its new location.**

**How to apply.**

1. **Assert the bytes anyway.** It is what caught a two-pass rewrite that deepened 47 targets twice,
   and it costs one comparison.
2. **Then read for the things whose meaning depends on where the text sits**: link labels, bare
   section marks, *"this document"*, *"below"*, *"the section above"*, and any relative path written
   as prose rather than as a link.
3. **Ask the checker what it declines to resolve**, and treat that list as the review checklist. Here
   both blind spots were already documented in the checker's own rules — the work was reading them
   as a to-do list rather than as an explanation.
4. **Do this after the assertion, not instead of it**, and record the repairs separately from the
   move so a reviewer can see that the move itself changed nothing.

Related: **L-39** on citing content rather than an address, **L-62** on the instrument that produced
the change not being the one that clears it.
