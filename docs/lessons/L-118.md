# L-118 — Embedding a rendering forks the input, and nothing downstream can tell it drifted

A tool that copies a *rendering* of a source into an artifact has forked its input. From that moment
the artifact holds an answer, not a question, and **every later correction — to the renderer, or to
the source — stops at the copy**. Nothing detects this, because the copy is well-formed, the gates
that read the artifact read the copy, and the source and the artifact are never compared.

The case: `quickview.py` embeds a Markdown source rendered to HTML inside a `<template>` in the
deck. Refreshing one shipped deck against its own unchanged sources produced **three** stranded
corrections at once, in five embedded documents totalling 99 163 bytes:

| Stranded in the deck | What it was | Reached the deck only now |
| :--- | :--- | :--- |
| 42 × `<p>---</p>` | T-107's thematic break, fixed long before | every one of the 5 sources |
| 19 → 3 shattered lists, 0 → 7 `<ol>` | T-121's list continuation, fixed the day before | 4 of the 5 sources |
| link targets, and a dropped file entry | an **edit to the source document itself** | 1 source |

The third row is the one that matters, because it is not a renderer fix at all. The source was
edited by a later commit; the deck kept quoting the version it was built from. A provenance feature
whose whole claim is *this is the document* was shipping a copy its own repository contradicted.

**None of the three was detectable.** `check.py` reads the deck, and the deck was valid. The
reference checks read documents, and `<template>` contents are not documents. The renderer's
self-test proves what `markdown()` produces *now* — never what some artifact captured a month ago.
Each instrument was correct and none of them was pointed at the join.

**The tool could not even fix it on request.** Wiring a quick view rewrites the very element the
tool searches for, so after the first pass the *add* verb refuses its own output — correctly, for a
different question (T-069). A fork with no way back is the state this lesson is really about: the
drift was not merely undetected, it was unreachable.

**How to apply.** When a tool embeds a rendering rather than a reference, it owes two things beyond
the embedding, and it owes them at the same time:

1. **A refresh verb**, whose refusals are derived from the artifact's state rather than borrowed
   from the add path — and which is a no-op, byte for byte, when the render already agrees. Without
   the no-op the verb cannot be trusted on a shipped artifact, because *refreshed* and *rewritten*
   look identical.
2. **A drift check** that re-renders and compares, so the fork is reported rather than discovered
   the next time someone happens to look. A refresh verb with no check just means the drift is
   fixable, not that anyone will know to fix it.

The general form: **the number of stranded fixes grows with the age of the artifact and is
invisible the whole time.** Age is the variable nothing in a green gate represents, so an artifact
that has been correct for months is exactly the one to re-derive rather than trust.
