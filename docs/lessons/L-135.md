# L-135 — A list of the homes to check is a second copy of what the homes are, and it goes stale on the day one is added

A sweep, a gate or a checker needs to know **which things it covers**. Writing that membership down
as a list is the obvious move, and it is wrong in a specific way: the list is now a *second copy* of
a fact the tree already holds. The tree changes; the copy does not.

**The failure lands at the worst possible moment.** A membership list is correct on the day it is
written and stays correct for as long as nothing is added — which is exactly the period in which
nobody needs it to be right. It goes wrong the moment a home is added, and a newly added home is the
one most likely to disagree with everything else, because nothing has ever reconciled it. So the
mechanism fails precisely when it would have paid.

**And it fails silently.** A broken pointer is loud: something names a thing that is not there. A
missing member is the opposite shape — nothing names it, so nothing can complain. The sweep runs, it
reports success, and the success is honest about a set that is smaller than the reader assumes.

**Measured 2026-08-23.** This project's `reconcile_targets` named two documents and one subdirectory
under `docs/`. `docs/` held fifteen top-level documents and four subdirectories, so thirteen
documents and three subdirectories sat outside every Create and Close staleness sweep — including
`docs/PRE-RELEASE-AUDIT.md`, the register
[T-219](../../tasks/T-219-pre-release-audit-of-the-whole-repository.md)'s forty-three cycles write
into, and `docs/AUDIT-METHOD.md`, which went stale that day and was repaired by hand. The hand repair
is the evidence: the process that should have caught it could not see the file.
[T-222](../../tasks/T-222-derive-the-reconcile-sweeps-membership-instead-of-enumerating-it.md) is the fix.

**It is a fourth recurrence, not a first.**
[taskmd's handoff config](https://github.com/uchimata2/taskmd/blob/master/.handoff/config.md) carries
three dated notes recording the same defect three times in that project, each landing when a home was
added. A shape that recurs four times across two projects is not carelessness; it is what listing
membership does.

**How to apply.**

1. **Resolve membership against the tree at run time.** A glob, a directory, a discovery walk — any
   of them derives the answer. `tools/check_all.py` already does this for checkers and decks, and
   its partition (ran / skipped with a reason / failed) is the shape to copy: discovery plus a
   forced verdict on every member.
2. **A depth-limited glob is still a list.** `docs/*.md` enumerates one directory while looking
   derived, and it fails on the day someone makes a subfolder. Write `docs/**/*.md`.
3. **Name the directory, not the files in it.** A folder entry keeps its own membership derived.
   This also reaches gitignored working directories, which are outside every git-based sweep and are
   where uncorrected statements survive longest.
4. **Where a list is genuinely unavoidable, make it a floor and say so** — the entry exists to catch
   homes that go stale *silently*, never to bound what gets checked.
5. **Suspect this first when a document was corrected by hand.** A manual repair to something a
   sweep was supposed to own is the observable symptom of a membership gap, and it is usually the
   only one you get.
