# L-131 — A correct measurement of the wrong subject passes every check you have

A broken instrument gets caught. It throws, or returns nothing, or returns something absurd, and
every one of those is loud. **An instrument pointed at the wrong subject is silent**, because
nothing about it is broken: it measures accurately, reports confidently, and the number it produces
is exactly the number that subject would give.

Measured 2026-08-22 under [T-215](../../tasks/T-215-the-frame-rate-instrument-and-a-number-with-its-machine.md).
A frame-rate instrument was built to run on a deck's heaviest slide. Three runs on real hardware
produced one usable row.

- **Run 1** reported *slide 1, 5 animated elements, 144.0 fps against a 144 ceiling*. Every figure
  correct. The slide was wrong: `.rise` is declared `.slide[data-played] .rise`, so a slide nobody
  has visited carries no animation to count, and a count taken before the walk sees the opening
  slide and zero everywhere else. It would have picked slide 1 **on every deck ever measured**,
  while printing a count that reads as a derivation.
- **Run 2** reported *slide 8, 6 animated, 1 looping, 144.1 against 144*. The right slide, and the
  right number. But **the reader looked at the slide and could see one thing moving.** Five of the
  six were entry animations, finished 600 ms after arrival and holding their end state — outside the
  measured window entirely. The same run named the deck after the slide, because `deck.js` rewrites
  `document.title` on every navigation and the page had asked itself what it was called.

**What did not catch any of it:** a green gate, a passing self-test, a clean console, and a
plausible number. The self-test verified that the overlay injected and the arguments arrived — it
could not verify that the thing measured was the thing meant, because the logic was internally
consistent with itself at every step. Headless caught nothing either: it produces no frames, so the
measuring path never ran there at all.

**What did catch it:** a person looking at the rendered slide and counting. `CLAUDE.md` rule 6 asks
for exactly that and this is the case it was written for — the artifact was correct, the gate was
green, and the label was false in a way only someone watching could see.

**How to apply.**

1. **Make the instrument report its subject, not only its result.** *144 fps* is unfalsifiable;
   *slide 8, one looping animation, 144 fps* can be checked against the screen by anyone. A figure
   that does not say what it measured cannot be audited by looking.
2. **Ask which of the things you counted were inside the window.** A count of *animations present*
   and a count of *animations running during the measurement* are different numbers, and the gap
   between them is invisible in a total.
3. **Distrust a subject the instrument selects for you.** Where a tool picks what to measure, seed
   the selection: run it against an input whose correct answer you already know, and check the
   choice rather than the output.
4. **A page cannot reliably name itself.** Anything the artifact rewrites at run time —
   `document.title` here — is a fact about its current state, not its identity. Pass identity in
   from outside.
5. **Budget for the real run to find things, and re-run after each.** Three runs for one row was
   not waste; it was the only channel through which any of this was visible.
