# L-128 — Two instruments agreeing proves they agree, and a shared error is the cheapest way to get that

A comparison check reads as self-verifying. It takes two independent measurements of one subject
and asserts they match, so a green result feels like it carries its own proof: two things had to
line up, and they did.

They only had to line up **with each other**. If both measurements are wrong the same way, the
check passes — and it passes *more* reliably than when they are right, because a shared error is
usually more stable than the thing it replaced.

Measured 2026-08-21. A rule compares one deck rendered at two resolutions and fails it if any
element sits more than a quarter of a design unit apart. It had been passing. Both renderings were
being measured before the entrance animation had produced a single frame, so 27 of 132 elements
were read exactly 18.00 design units from where they settle — the animation's full travel, to the
digit. Both readings were wrong, identically, and the rule reported agreement. **The deck was never
compared to itself; two copies of the same artefact were.**

**The intermittency was the rule working, not failing.** Occasionally one rendering produced a
frame the other did not, the two errors stopped matching, and the check went red — on a deck with
nothing wrong with it. So the fault presented as a flaky check, and the obvious reading of a flaky
check is *the threshold is too tight*. Widening it would have made the silence permanent.

**How to apply.**

1. **Ask what a comparison is anchored to.** Two measurements of a subject are anchored to each
   other and to nothing else. Nothing in the pair can detect an error both share, and no number of
   repeats helps: repetition measures stability, and a shared error is stable.
2. **Anchor at least one reading to something outside the pair.** A known-settled state, a value
   derived a different way, a fixture whose answer is fixed. Here it took one run with animation
   pinned off — a second kind of measurement, not a second instance of the first.
3. **Read an intermittent comparison as a lead, not as noise.** It is the one moment the shared
   error stopped being shared, which makes it the only evidence the pair can produce about itself.
   Chase the disagreement; do not tune it away.
4. **Suspect a guarantee that a caller can decline.** The pin that would have settled the page
   existed and was behind a flag, so the consumer taking screenshots asked for it and the consumer
   issuing verdicts did not. **A guarantee with an opt-out is an exception without a name**, and
   the caller that opts out is not chosen by design — here it was simply the one nobody revisited.
5. **When the fix removes the variable, stop hunting the trigger.** The prior task on this symptom
   could not reproduce the trigger and recorded that as an open limit, correctly: its fault
   survived one. This one does not — with the page settled there is no animated quantity left for a
   trigger to move — so the same unreproduced trigger blocks nothing.

The general shape: **agreement is evidence about a relationship, never about a subject.** Ask what
each side was measured against before reading a match as a fact. Related: **L-13**, since two
readings of one quantity is the second-copy shape again, and **L-119**, which is this rule's other
way of comparing the wrong two things.
