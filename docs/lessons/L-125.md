# L-125 — Before amending a rule, read what its gate actually tests

Found 2026-08-21 (**T-187**), opening DS-140's closed motion vocabulary into a suggested set.

**The task record listed six dependent rules and one self-test, measured two days earlier, and the
list was right.** It was also not the thing that decided the work. DS-141 — *entry and transition
animations max 500 ms* — appeared on it as *needs a stated exception condition that does not depend
on a name*, one row among seven. What made it the whole design was a fact that lives in the gate and
in no document: `ds141_durations` waived the cap for any declaration reading `--pulse-dur` or
`--current-dur`. **Two token names were the entire implementation of *is one of DS-140's four*.**

**So removing the names would have removed the check, silently and in the good direction.** Every
deck would still have passed. The cap would have gone on being cited by five documents and enforced
by nothing, and the way anyone would have found out is a deck shipping a four-second entrance.

**Why the rule's own text does not warn you.** A rule states an obligation; a gate states a
mechanism, and the mechanism is free to be a proxy. Here the proxy was a good one for as long as the
vocabulary was closed and worthless the moment it opened, and nothing in DS-141's prose says which
of its clauses a machine is actually reading. The ruleset records *what must be true*. It does not
record *what is currently checkable, and by what stand-in*.

**The rule.** When amending a rule, open the code that checks it before writing the amendment, and
ask what the check would test after the edit. **A `hard`/`auto` rule whose check quietly becomes
vacuous is worse than a rule downgraded on purpose**, because the column still says `auto` and the
account still counts it among the 121.

**How to apply.** For each rule an amendment touches, find its checker and answer one question in
writing: *after this edit, what input still fails?* If the answer is *none*, the amendment owes a new
mechanism — here, a declared licence (`--motion-long`) replacing an inferred one — and the proof is a
seeded defect run in **both** directions: the unlicensed case fails, the licensed case passes. One
direction proves half of it; a check that fails everything is as broken as one that fails nothing.

**Two smaller findings from the same run, both about instruments.**

- **A seed that changes nothing may be measuring a second implementation.** Deleting the
  `prefers-reduced-motion` CSS block left DS-143 passing, because `deck.js` honours the preference
  independently. The check was right and the seed was incomplete — **L-124** from a new angle: not the
  wrong *form*, the wrong *half*.
- **Prove which entry point runs the guard.** `audit.py`'s self-test is invoked by `check.py` and not
  by `audit.py`'s own `main`, so mutating a row and running `audit.py` reported a clean exit and
  looked like a missing guard. The guard was there; the instrument was wrong.
