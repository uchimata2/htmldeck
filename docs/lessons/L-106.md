# L-106 — A verdict cannot verify a change to a matcher; compare the artefact it derives

Met 2026-08-16 (**T-169**). The figure binder learned to read a time word before its numeral —
`Month 4` as well as `4 months`. Four decks in this repository build a ledger. The verdicts said the
change was clean on three of them, and on one of those three it had **deleted a real figure**:
`sort-window`'s `5%` fell out of the ledger and `FIG-1` stayed green either side, because the deck
had no unsourced figure before and none after. A verdict is a fold, and this one folds a hundred
rows into a boolean. The row that vanished was never in the boolean's answer.

**What the row-by-row comparison bought, in one run:** the lost `5%`, its cause — a guard reading
`5%The` as a hyphenated compound, itself an artefact of `runs()` deleting inline tags — a trailing
comma captured into a value, five figures newly bound, one phantom removed, and four figures on the
reference deck that had never been visible to any check here. Six of those seven cost nothing to
find and only one of them changes a verdict.

**The reason is not that verdicts are coarse. It is that a matcher changes the population.** A rule
answers a question *about a set*, and widening what enters the set changes which members the
question is asked of. So a stable verdict is evidence about the fold, not about the change — and the
two decks whose verdicts did move needed the rows anyway, to say whether the movement was damage or
a finding. The instrument that answers the question is the same one either way.

**Then the same mistake again, one altitude up.** The ledger comparison is the artefact of the
*module* that changed, and the module has other readers. `audit.magnitude` reduces a cited figure to
its number for a different rule in a different file, it did not know the new form, and `DS-231`
failed the reference deck for citing behind a click a number that slide shows three times — a false
alarm invisible to every ledger diff, because no ledger row is wrong. **The artefact to compare is
the one the consumer sees, not the one the change sits closest to.** Comparing all 114 gate rows on
four decks took one command and settled it: two row texts move, one verdict moves, 110 rows
identical.

**The criterion to write is *no row moves*, not *no gate moves*.** T-169 wrote *no shipped deck
moves* and it was read correctly only because the comparison existed; a verdict reading of the same
words would have passed the run that dropped the `5%`. When the deliverable is derived — a ledger,
an index, a manifest, a report — snapshot it before, snapshot it after, and diff. The snapshot is
ten lines and it is the only thing that sees a silent deletion.

**And expect the honest red.** The same comparison showed the reference deck failing `FIG-1` on four
dates its sources do not carry. A check that stops being blind reports defects that were always
there, and the first instinct — narrow the matcher until the shipped artefact is green again — is
the failure wearing the acceptance criterion as cover. Route it (**T-170**) and leave it red.
