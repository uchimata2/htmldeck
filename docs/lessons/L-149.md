# L-149 — A container answers with everything nested in it, including documents it only cites

Found 2026-08-30 in [T-259](../../tasks/T-259-nothing-prints-what-a-slide-actually-contains.md),
while building a printer that reads a slide's own answer for every field its specification entry
claims. The obvious implementation reads the slide's `<section>` and pulls each field out of it. On
slide 4 of [`../../examples/sort-window/sort-window.html`](../../examples/sort-window/sort-window.html)
that section is **9,826 bytes, of which 4,056 are the slide** — the other 59% is
`<template class="qv-src">`, one per quick view, each holding a **source document the slide merely
links to**.

So the first run answered *eyebrow*, *headline*, *drawn label* and *bottom line* with text from a
markdown file the slide cites. Every one of those answers was well-formed, plausible, and about a
different document.

- **Nesting is not containment in the sense a reader means.** *What is on this slide* and *what is
  inside this slide's markup* are two different sets, and the markup gives you the second. Anything
  a container carries **on behalf of** something else — a template, an inert payload, a cached copy,
  a `<noscript>` fallback, a print-only variant — is in the second and not the first.
- **The failure has no symptom.** A field answered by the payload is not empty, not malformed and
  not obviously foreign; it is one document's sentence printed under another document's heading. A
  test written from a slide that happens to carry no quick view passes forever.
- **Cut the payload before reading any field, not per field.** Excluding it inside each field's
  own pattern makes correctness a property of ten patterns and of every one added later. One cut at
  the top makes it a property of the function.

**The same shape produced the reverse fault ten minutes later**, and it is worth naming because it
looks unrelated: a figure sits inside a `.body` wrapper, so *body copy* and *drawn labels* both
answered with the chart's eleven axis ticks and value labels. Nothing foreign was printed that
time — the slide's own text was printed twice, under two field names, so a reader holding the
entry's `Text.` line against the deck read axis ticks as a paragraph. **Two fields reading one
container must partition it**; where they do not, one of them is answering for the other.

**What to do with it.** Before reading a field out of a container, ask what the container carries
that is not its own — and assert it in a fixture, with the foreign text marked so a leak names
itself. `slidefacts.py`'s fixture ships a `<template>` whose every line reads `PAYLOAD`, and its
self-test fails any field whose answer contains that word. A trap that cannot be seen in the output
has to be seen in the test.
