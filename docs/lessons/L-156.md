# L-156 — A finding names the instance somebody hit; only a tool finds the ones nobody looked at, and the document that recorded the finding is a likely host

Found 2026-09-02 in [T-237](../../tasks/T-237-the-release-machinery-and-its-record.md), closing
`PR-16`. The audit reported one blank line splitting one table, in
[`PUBLISHING.md`](../PUBLISHING.md) §8.1, and asked as a hypothesis whether a check for the shape was
worth writing. The check took an afternoon and reported **four**: the one that was reported, two in
[`RELEASE-PHASES.md`](../RELEASE-PHASES.md)'s own phase tables, and one in a task file.

- **The reported instance is a sampling artifact.** Somebody read that table, on that day, for
  another reason. It says nothing about how common the defect is — only that one reader's path
  crossed one instance of it. Fixing it and closing the row records the sample as the population.
- **The other instances sit where nobody reads, which is why they survived.** All three unreported
  ones were in tables nobody had cause to render: struck-through rows of completed work, and a
  findings table inside a closed task. A defect that only shows when a document is read is not found
  by reading documents.
- **Suspect the document that recorded the finding.** Two of the four were in `RELEASE-PHASES.md`,
  which the same audit was reading at the time. A register and its subject are written by the same
  hands under the same habits, so the shape being recorded is disproportionately present in the
  record — and it is the last file anyone thinks to scan.
- **Confirmed the same day, on an unrelated finding.** `PR-27` reported two closed tasks carrying no `shipped_in`; the same batch counted **44**, and the project's own release history had recorded the shape twice before that at eight and at one. Two audits, two reported instances, two populations an order of magnitude larger. Where a finding is mechanically decidable, treat the number in it as a lower bound and nothing else ([L-158](L-158.md)).
- **The cost asymmetry decides it, not the count.** Deleting one blank line and writing a checker for
  the class differ by an afternoon; the fix that reaches only the reported instance has to be paid
  again at every later discovery, and each of those costs an audit cycle to find. Where the class is
  mechanically decidable, measure the class before fixing the instance — the measurement is what
  tells you whether the tool was worth it, and here the answer was four to one.
