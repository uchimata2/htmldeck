# L-133 — An ordinal cited in prose is a running total in disguise, and fixing one numbering in a document does not fix the other

**L-08** says a stored copy of a derivable fact goes stale. A count in prose is the obvious case and
gets noticed. **An ordinal is the same fact wearing a grammatical costume**, and it does not get
noticed, because *the eighth reopening is four tasks* reads as a description of those four tasks
rather than as an assertion that seven came before them.

The costume does two things. It **hides the arithmetic** — no digit appears where a reader scans for
one — and it **spreads the value across the document**, so the figure is not in one sentence to be
corrected but in every sentence that ever named a position. A total decays in one place. Ordinals
decay everywhere at once, and each one reads locally fine.

Measured 2026-08-22, in `docs/RELEASE-PHASES.md`. Its `PH1` section stated *the phase has reopened
eight times* and, four screens down, *the ninth reopening is three tasks* — neither marked as
superseding the other, both in the same section. Under them sat *a fourth*, *a sixth* and *a fifth*
joined, in that order; *these six are `0.2.3`* against *four of the five came from looking*; and two
sentences describing the phase as still open, which it had not been since the release shipped. **One
figure stated twice turned out to be four things stated twice.** No gate could see any of it: nothing
reads the number, so nothing can disagree with it.

**The second half is the expensive one.** This document had already been fixed for exactly this
defect. `tools/docs/findings.py` records that five of its execution-order notes cited row numbers
until an insertion cascaded into the prose — four hand renumbering passes in two days — and the notes
cite task ids now, with the remaining invariant under a checker. That fix landed and **the other
numbering in the same file was never looked at**, because the repair was scoped to the table that
hurt rather than to the habit. A document has as many numbering schemes as it has sequences, and
curing one teaches nothing to the next unless somebody goes looking.

**How to apply.**

1. **When a numbering defect is fixed, sweep the same document for other sequences before closing.**
   The fix is cheap while the mechanism is in hand and expensive once it is not. Ask what *else* here
   is cited by position.
2. **Replace the ordinal with the item's own identifying fact** — a release, a date, an id, a source.
   Those do not move when the set grows. This is what the execution-order notes did, and it is what
   the reopening prose does now.
3. **Prefer deleting the sequence to maintaining it.** Ask what consumes the number. Where nothing
   does, a running index is a maintenance obligation bought with no return, and **L-08**'s argument
   applies at full strength: say what is countable and point at it. `CLAUDE.md` shed two such counts
   on 2026-08-14; this document shed the third on 2026-08-22.
4. **A count nobody consumes still has to be right, or it teaches readers to distrust the document.**
   That is the reason this is not merely tidying: a section that contradicts itself in the open costs
   the credibility of the sentences around it that are load-bearing.
