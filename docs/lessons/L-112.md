# L-112 — A self-test that asserts repository state fails on exactly the commits that change it

Caught 2026-08-17 (**T-176**, raised out of **T-109**). `tools/deck/shell.py`'s first fixture made
two assertions off the tracked reference deck: that `cut` round-trips on it, and that what the cut
leaves **is** `shell/shell.html`. The first is a claim about the tool. The second is a claim about
the repository, and it goes false the moment anyone edits `shell/shell.html`.

`main()` runs the self-test before every subcommand and exits when it fails. So adding one `<p>` to
the shell locked every command in the file — including `sync`, **the command whose entire job is to
carry that edit into the decks**. The message said `SELF-TEST FAILED - the tool itself is wrong;
anything below means nothing` while the tool was working correctly and one file was one edit ahead.

The tell is that the assertion was a **duplicate that lost its verdict on the way**. `check()`
already reported the same drift by name as `SKELETON`, `sync` already repaired it, and three
fixtures below asserted both. Restated inside the self-test, a serviceable finding became a fatal
one in the one place that cannot offer the repair.

**How to apply.**

1. **A self-test may assert what the tool does, never what a tracked file currently contains.**
   Build the fixture — here `new()` fills the shell's own regions, so cutting it and comparing the
   remainder to `shell/shell.html` asserts `cut` and `fill` and nothing else. Both original claims
   survived; only their subject changed.
2. **Where a real artifact is genuinely better input, keep it for the property that cannot go
   stale.** The reference deck still proves losslessness — `fill(cut(x)) == x` is true of it however
   far the shell moves.
3. **Before restating a check inside a self-test, ask what already reports it and what repairs it.**
   If the answer is *this same tool*, the restatement can only subtract.

**The shape generalises past self-tests.** Any precondition run before every command is a place
where a fact about the repository becomes a fact about the tool. **L-77** is the same file's other
case, from the other direction: there, two checks disagreed about what a file *is*, and one edited
it through the half it could not see.
