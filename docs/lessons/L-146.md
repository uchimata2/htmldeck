# L-146 — A guard true of every case is only half an off switch; what settles it is whether another document already mandates it

[L-144](L-144.md) says to measure the population a guard would exempt, because a rule that has never
fired has no prior count to protect it, and a guard admitting all of them is an off switch whatever
it is called. That is the alarm. **It is not the verdict**, and reading it as one refuses guards that
are doing real work.

Found 2026-08-29 in [T-277](../../tasks/T-277-put-motion-back-inside-the-more-menu.md). The owner
reversed DS-218's placement clause — a stop control one click inside a persistent, keyboard-operable
menu counts as reachable — which left the rule deciding *the control exists and its opener can be
reached*. Measured before the check was written: the opener is a persistent, keyboard-operable
`<button>` on **5 of 5** built decks. L-144's shape exactly, and by its first two points the clause
was an off switch wearing a plausible sentence.

**Its third point decided the other way.** DS-100's guard was refused because two documents this
project already owned — the component contract and DS-202 — *mandated* the condition on every slide,
so nothing could ever fail it and no drift could ever make anything fail it. Here nothing mandates
it: `COMPONENT-CONTRACT.md` §3.4's table binds `.btn` to `.chrome` as `1+` and names no opener at
all, and `PR-78` had already **measured** what a tail missing one of these buttons does — the deck
reports `data-preflight="fail"` and renders 0 of 13 slides — while `shell.py check` and
`component.py check` both pass it. The condition is true today and nothing holds it true tomorrow.

**The distinction, in one line.** *All cases pass today* is a fact about the population. *Nothing
could make a case fail* is a fact about the contracts. Only the second is an off switch, and the
first is evidence for it rather than proof of it.

**How to apply.**

1. **Run L-144's measurement first — it is still the cheap alarm.** A guard admitting every case is
   the signal to stop and look, and skipping it means never asking.
2. **Then ask who holds the condition true.** Search the project's other contracts for the property,
   the way L-144's third point says. A condition another document mandates cannot fail and the guard
   is decoration. A condition nothing mandates can fail, and a guard is what makes the failure
   visible.
3. **The strongest evidence is a measured failure nothing else catches.** `PR-78` was worth more here
   than any amount of reading, because it showed the failure is reachable *and* showed the other two
   gates passing it. Look for a register row before arguing from the code.
4. **A guard that survives this owes a stated reason at run time.** A boolean printed over a
   condition nothing else guards tells a later reader nothing; the check now emits *which* step of
   the walk succeeded, so a pass is checkable by eye rather than trusted.
