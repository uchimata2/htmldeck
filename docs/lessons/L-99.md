# L-99 — A portability test that looks for your own names cannot see theirs

Caught 2026-08-14 (**T-138**). A document written to be copied into any project carried an explicit
extraction test — *it names no file of the repository it was written in* — and passed it cleanly. It
was still unusable by a reader on a different agent, because it assumed one product's concepts
throughout: a per-capability override key, a connector switch, three null results measured against one
vendor's settings files, and a whole vocabulary of things a different agent does not have.

**The test was looking in the wrong direction.** *No local file names* checks what leaked **out of**
this project. Portability also fails on what leaked **in from** the environment the work happened in —
and that half has no obvious search term, because the borrowed vocabulary reads as ordinary technical
English to whoever borrowed it.

**How to apply.**

1. **Write the exclusion list before the sweep**, as words rather than as an intention: name the terms
   your environment supplies and grep for them. A rewrite verified by re-reading is verified by the
   person least able to see the assumption.
2. **State the boundary in the document, not only in the task.** Some product names must survive — a
   quoted query, a cited source, a technique that has a name. A rule of *no product names* is wrong
   and will be broken silently; a rule of **the method and the findings name no product, the evidence
   does** can be applied by the next writer. The line falls between *what you must do* and *what was
   found*.
3. **Move the mechanism, do not delete it.** One machine's key forms and null results are evidence and
   belong in the local half, dated and marked. A portable document states the *shape*; the instance
   stays where the machine is known.
4. **Say what you could not test.** The only real check is a reader on another agent, and it is
   usually unavailable. Record that rather than letting a grep stand in for it.

which is the banding half of the same audit's mistake.
