# L-154 — A token that enters the context at call t is paid about 2 + 0.1 × (N − t) times, so the earliest reads are the dearest and a resume compounds like tier 1

Found 2026-09-02 in [T-287](../../tasks/T-287-audit-what-a-session-pays-per-turn-and-why-it-grows.md),
from one session's transcript read for the token fields of every API call, with the harness's own
weights: a cache write 2, a cache read 0.1, an output token 5. Fourteen calls in, fresh content was
45% of the weighted spend, the session's own writing 25%, and the carried context 30% — and the
carried term overtakes the fresh one once the context exceeds about twenty times what a call adds.

- **Where a byte enters decides what it costs, not only how big it is.** A read at the fifth call of
  forty is paid five and a half times its size; the same read at the thirty-fifth, two and a half.
  The resume read path is the earliest thing a session does after loading, so a section read whole
  because a pointer named the section is carried for the whole session. Point at the paragraph.
- **A session boundary is a cache miss on purpose.** It re-pays the start context and the read path
  at the write rate — about 190,000 weighted tokens here — against about 14,000 per call to carry a
  140,000-token context. The rhythm of one session per task buys continuity and a fresh runway; it
  does not buy tokens until the next session runs some thirty calls at the smaller context.
- **The owner's *exponential* is a quadratic.** Per-call cost is linear in the context; the sum over
  a session is not, and the sum is what a bill shows. Nothing here is exponential, and the lever is
  what each call adds — which is why a gate that prints one line green (L-153) and a document a
  pointer can address by paragraph are the same finding at two altitudes.
- **The instrument reads one session and says so on every figure.** It is evidence for that
  session; it is not a measurement of the tree, and a figure from it is never carried into a rule
  without the date and the session it came from.
