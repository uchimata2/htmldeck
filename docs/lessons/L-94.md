# L-94 — A budget written as a relation must fix its comparison set

Found 2026-08-14 by [T-143](../../tasks/T-143-split-the-release-chronology-out-of-claude-md.md),
one day after [`L-88`](L-88.md) chose the relation's second term and did not close this.

The bound on the always-loaded file is *smaller than the smallest document it defers to*. **The
remedy the bound exists to prompt is splitting content out — and a document split out of tier 1 is
smaller than tier 1.** So if the new document counted as a term, every cut would create a smaller
comparison and the bound would ratchet away from the file chasing it. **The rule would be
unsatisfiable by the one action it was written to cause**, and nothing in it said so.

The set had been closed in practice and never in writing: five documents were named, and a sixth the
file plainly defers to had never been in the list. Practice was right and unrecorded, which is the
state where the next reader adds the obvious term and breaks the rule while obeying it.

**The second failure is that both terms move.** The smaller side changed hands the same morning the
debt was written down — one deferred document fell from 23,210 bytes to 11,407 — so the statement
was wrong in *both* numbers within hours, and the task raised to fix it had copied the error forward.

**How to apply.**

1. **State the comparison set, not just the relation.** Which documents are terms, and by what
   property they qualify — here, tier 2 — so a new document has a decidable answer.
2. **Test the relation against its own remedy.** Apply the change the budget is meant to cause, on
   paper, and check the bound is nearer. If the remedy moves the target, the set is wrong.
3. **Re-measure both terms, never one.** A relation has two moving numbers and the smaller one is the
   likelier to have moved, because it is the smallest thing in the set and small documents change by
   larger fractions.
4. **A rule that reports its own compliance still reports a stale number.** Self-measurement is not
   self-updating; the figure is only as fresh as the last person who ran the command
   ([`L-90`](L-90.md), [`L-92`](L-92.md)).
