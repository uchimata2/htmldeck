# L-167 — A defect in how a pattern closes an element is a class, so sweep for it

Found 2026-09-14 by [T-303](../../tasks/T-303-close-a-slidefacts-element-at-its-own-tag-find-every-control-and-make-readabilitys-ledger-add-up.md).

`slidefacts.py` closed an element at the first matching close tag, so a `.body` whose first child was
a `<div>` lost every sibling after it. The fix balanced the tag. The ledger built in the same task then
found the same cause in a second helper: `<svg\b.*?</svg>` ended a figure at the first icon nested
inside it. A search for `.*?</` found the idiom in five more tools.

Most of those are safe, and the tag is the reason. `script`, `style` and `p` cannot nest, so their
first close is their own. A tag that can nest, such as `div`, `section` or `svg`, is right only while
nobody nests it.

**How to apply.** When you fix how one pattern closes an element, search for the idiom everywhere
before you close the task. Sort each match by whether its tag can nest. For the ones that can, count
unbalanced matches on real input, and record the count with its date.
