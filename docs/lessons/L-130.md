# L-130 — An idiom carries the guarantees of the instrument that reads it, not the ones its syntax suggests

Reuse a declaration idiom that already works, and what you inherit is the *syntax*. The properties
that made it safe belong to the tool that reads it, and they do not travel with the spelling.

This project declares three facts on the artifact and reads them back: `--motion-kind` (DS-237),
`--motion-long` (DS-141) and `data-disc` (DS-230). The first two are custom properties, and both are
read by a **regex over the CSS source text**, rule body by rule body. So a declaration binds to the
rule it is written in, and an element that declares nothing has nothing said about it. That is the
guarantee — and it comes from the scan, not from the property.

A fourth fact, `--motion-subject`, was added on the same idiom for DS-142. But DS-142 is decided by a
**live probe on `getComputedStyle`**, because whether an element is animating is not a fact about one
rule. Custom properties **inherit**. So an element declaring nothing does not read as nothing; it
reads as whatever its nearest ancestor said. A glow nested inside a flow that declared `live` would
have been exempt by descent.

The defect being fixed was an allow-list of one class name. Copying the idiom without its instrument
would have replaced it with an exemption one **subtree** wide — larger than the defect, wearing the
shape of the fix, and green on every deck in the corpus because none of them nests one animation
inside another.

Measured 2026-08-22, under [T-214](../../tasks/T-214-ds-142s-checker-is-an-allow-list-of-one-class-name.md).
Registering the property `@property{inherits:false}` closes it, at the point the probe measures
rather than by a rule about where authors may write the token. The seed that holds it —
`ambient-glow-inheriting-a-live-subject` — reports **two** ambient elements against the unregistered
property and **one** against the registered one. Both are caught either way, so the pass/fail verdict
is identical in both directions and only the count distinguishes them.

**How to apply.**

1. **Name the instrument before reusing the idiom.** *We already declare things this way* is a claim
   about syntax. Ask what reads it: a source scan, a computed-style probe, a DOM query. Each has a
   different answer to *what does an undeclared element read as?*
2. **For anything read off computed style, settle inheritance explicitly.** Registering it is one
   line and it is enforcement; a convention that authors declare on the right rule is not.
3. **Check that the fix is not bigger than the defect it replaces.** A name-based allow-list and an
   inherited exemption are both over-admission — the second is just harder to see, because nothing
   in the corpus triggers it.
4. **Seed the mechanism, not only the rule.** A seed whose verdict is unchanged by the bug is still
   worth keeping when a *number in its row* moves; assert the number, or the guard is decorative.

Related: **L-125**, which says a check must bind on structure rather than on vocabulary — this is the
next question after that one, since structure still has to be read by something. **L-129** for the
direction that had never been observed, and **L-39** for the comment that claimed a re-derivation the
code below it never had.
