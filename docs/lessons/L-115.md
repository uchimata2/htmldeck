# L-115 — Probe the mechanism a rule names, never the noun the rule contains

A rule is a sentence with nouns in it, and the nouns suggest where to look. **They are usually the
wrong place.** A rule about *charts* is not enforced in whatever file has `chart` in it; it is
enforced wherever the behaviour it governs is implemented. Searching for the noun answers a question
about vocabulary and reads as an answer about existence.

The case: [T-119](../../tasks/T-119-audit-the-ruleset-for-rules-that-cost-more-than-they-return.md)
was raised on the claim that DS-146 and DS-147 are dead legislation — two rules governing chart
behaviour with no chart component — on this evidence:

```
grep -c -i "chart" shell/components.css   →  0
```

The count is right. Both rules are alive: DS-146 and DS-147's `countUp()` are both in `shell/deck.js`,
each carrying its rule id in a comment, and both ship in every deck this repository gates. The
subject is there too — `examples/reference-deck.html` draws a line chart in hand-authored SVG.

**The probe was not merely aimed at the wrong file. It was aimed at a file the ruleset forbids the
answer to be in.** DS-122 says *no chart library, hand-written SVG*, so a `.chart` class in the
shared stylesheet is the one form the rule prohibits. A zero there is the ruleset working, and it
was read as the ruleset legislating for nothing.

**How to apply.** Before concluding a rule has no subject, take the rule's **verb** and ask which
file performs it — behaviour is in the script, look is in the stylesheet, structure is in the deck —
then search there for the **rule id**, which this project writes into the code that implements a
rule. A negative result from a noun search is not evidence of absence; it is evidence about naming.
The same shape as **L-114** one layer up: the instrument returned a confident zero because it was
pointed at text that could not contain the answer.
