# L-141 — A threshold found by varying one thing names that thing as the cause only if nothing else changes with it

A report arrives with a clean measurement: 18 passes, 19 fails, and the count then rises one per
slide. The variable that was moved is length, so the cause is read as length, and the remedy is
written against length. Both are wrong when moving that variable **switched something else on**.

Found 2026-08-29 closing [T-263](../../tasks/T-263-ds-217-fails-on-any-deck-past-eighteen-sections.md),
from ClaimAI adopter report `002`. The finding was real and the threshold was real. But the ruler
changes **mode** past its measured capacity — the small ticks stop being targets and become marks of
a second, smaller size — and the actual defect needed that second size **and** two large marks
sitting side by side, which is a stage holding a single slide. Length was a precondition, not a
mechanism. This repository's own reference deck spliced to 19, 25 and 43 slides passed every time,
because nothing about splicing puts two section marks together.

The report's stated cause followed from the same reading — *sub-pixel rounding across many flex
items* — and dissolved on measurement: the rounding is **1e-4 CSS px across 43 ticks**, four orders
of magnitude below the half-pixel bucket it was said to break. Its first proposed remedy, a
tolerance, would have changed nothing at all while looking like a fix that worked, which is the
shape [L-125](L-125.md) warns about one layer up.

**How to apply.**

1. **Reproduce before repairing, on a subject you control.** The one command that mattered here was
   splicing this project's own deck to the reported length and watching it pass. A remedy written
   without it would have shipped against the wrong variable and been believed, because the seeded
   proof would have been seeded in the wrong place.
2. **When the reproduction fails, the report is not wrong — the variable is.** Ask what *else*
   crosses a boundary at that value. A mode change, a fallback, a cache filling, a layout switching
   from one algorithm to another: each gives a threshold in a variable that is not the cause.
3. **Look for the second condition.** A precondition plus a trigger is the usual shape, and the
   trigger is usually structural rather than numeric — an adjacency, an ordering, a missing member.
   It is what the reporter's deck had and yours does not.
4. **Then make the structural fixture a command.** Length is easy to vary and structure is not, so
   the structural fixture is the one that dies with the session unless it is written down. Here it
   became `longdeck.py --solo-stage`, with a self-test asserting both that it produces the
   arrangement and that a plain splice does not — the second half being what stops the proof going
   vacuous.
5. **Say in the closure which of the report's claims you refused, and with what measurement.** A
   record closed as *fixed* over a cause nobody re-tested teaches the next reader to trust the next
   stated cause.
