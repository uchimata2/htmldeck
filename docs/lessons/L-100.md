# L-100 — Two rules that are both right can block the same fix; report the collision, do not pick

Met 2026-08-14 (**T-153**), closing an audit's phase 2. The remedy was trivial and unarguable: the one
figure governing what every session pays should be checked by something rather than remembered by
someone. It had drifted 174 bytes since the last task touched it, and the checker that exists for
exactly this shape reads it as unanchored.

**Both routes to it broke a rule the project had already settled.** Pasting the measuring command's
output beside the figure lands new bytes on the surface the whole audit had just been cutting. Moving
the figure to a document that can be gated contradicts the rule that a figure about that file cannot
be corrected anywhere else — a rule written *because* a previous session had recorded it elsewhere and
left it wrong.

**Neither rule is wrong, and neither is negotiable by whoever happens to be holding the task.** The
temptation is to rank them silently — to decide that this one is more important today — and ship the
fix. That converts a decision the owner would want into an edit nobody will ever find, and the losing
rule stays on the page contradicting the code.

**So the collision is the deliverable.** Name both rules, name what each forbids, say plainly that
they are both the project's own, and stop. The obligation stays open and visible, which is worse than
a fix and much better than a fix that quietly overrules a settled rule.

**The tell that you are in this situation rather than merely stuck:** every route you can see is
cheap, and each one is blocked by a *different* rule. A genuinely hard problem has one hard route. A
collision has several easy ones, all forbidden.
