# L-166 — A capture proves a state change only where the two states look different

Found 2026-09-14 by [T-305](../../tasks/T-305-let-render-py-see-an-svg-paint-change-a-scripted-hover-and-a-figure-painting-over-its-neighbour.md).

The fix made `render.py state --hover` run a deck's `mouseenter` listeners. The first real case was
the reference deck's first ruler tick, and its capture showed the label `CLAIM`. That is also the
label at rest, because the first tick previews the stage the deck opens on. So the capture looked the
same whether the listener ran or not, and it was no evidence of the fix.

The second tick previews `WHY NOW`. Its capture shows `WHY NOW` with the fix and `CLAIM` with the fix
removed, so the pair is evidence.

**How to apply.** Before a capture counts as proof that a state was reached, check that the state
differs from rest in something the picture shows. If it does not, pick a case where it does, or read
the change from the tool's report instead of from the picture.
