# L-126 — A published benchmark is stated in its own deployment's units, not in yours

Found 2026-08-21 (**T-113**), comparing four chart libraries for a deck opened from `file://`.

**Every chart library on the market publishes a size figure, and every one of them is gzipped.**
TanStack Charts' own comparison page states 37.60–43.56 KiB for itself and 44.70–58.21 KiB for
Chart.js. Both numbers are true. Neither is the number a deck pays.

| | What the vendor quotes | What a `file://` deck pays |
| :--- | ---: | ---: |
| TanStack Charts, a financial slide's marks | 55,830 gzip | **165,077 raw** |
| Chart.js 4.5.1, `chart.umd.min.js` | 70,506 gzip | **208,522 raw** |
| ECharts 6.1.0, `echarts.simple.min.js` | 169,097 gzip | **500,315 raw** |

**The gap is between two and five times, and it decides the answer.** At the quoted figures ECharts
looks like a third of the reference deck and is affordable. At the figures a deck actually pays it is
1.26 times a whole deck, and it is out on gate 1 alone.

**Why the number is not wrong, which is what makes it dangerous.** A library's normal deployment is
an HTTP response with `Content-Encoding: gzip`, so gzipped bytes are the honest unit *there*. This
repository's deliverable is one HTML file the recipient double-clicks. There is no server, no
negotiation and no transfer encoding. The vendor and the adopter are both quoting bytes, in good
faith, about different transports — and the word *bytes* hides the difference completely.

**The rule.** Before comparing a published measurement with your own constraint, name the unit and
name the deployment it assumes. Where they differ, **re-measure in your units** rather than adjusting
the published figure by a factor: the factor is a property of the payload, not a constant.

**How to apply.** Download the artefact the deliverable would actually carry, measure it locally, and
put the vendor's figure in a second column so the difference is visible instead of resolved. The
second column is what stops the next reader re-importing the published number. A cheap check that
you have the right unit: reproduce a figure your own project measured before. R5 recorded Chart.js at
203.6 KB on 2026-08-06; `chart.umd.min.js` measured 208,522 B — 203.6 KiB — two releases later, which
confirmed the unit and the method in one line.

**The general form is wider than size.** A benchmark's latency assumes a network you do not have; a
throughput figure assumes cores you did not allocate; a *works offline* claim assumes a service
worker a local file cannot register. **The measurement is sound and the deployment is the variable**,
so the question to ask a published number is never *is this true* but *true where*.
