# L-108 — A tool's safety guarantee defines work it cannot do; name the gap, never weaken the guarantee

Met 2026-08-16 (**T-166**), on the first real adopter upgrade this repository ever performed.
`shell.py sync` installs the shared shell into a deck built against an older release, and its whole
claim is that **every per-deck region comes through untouched** — it asserts this on the adopter's
own file and refuses to write if one moved. That property is what makes it safe to run on a 250 KB
file nobody can read.

**The same property is why the upgrade did not finish.** T-106 added `--qv-measure`: the shared block
*reads* it, and every deck *declares* it in its own theme region. The block is shell and syncs; the
declaration is a theme value in a per-deck region, so `sync` correctly refuses to touch it and
therefore installs a shell reading a token the older deck never declared. `sync` said success,
`shell.py check` said clean, and the next gate failed `DS-013`. **Both commands an adopter is told to
run reported yes.**

**The tempting fix is to let `sync` write the token, and it is the wrong one.** It buys one token at
the cost of the sentence the command is trusted for, and the next release adds a region rather than a
token. The guarantee is not an obstacle to route around; it is the reason the tool is usable at all.

**So the rule is: the tool that holds both halves owes a report, even where it owes no write.**
`sync` is the only command that sees the incoming shell *and* the receiving deck, so it is the only
one that can detect this — and reporting costs the guarantee nothing. The write went to a separate
command with a narrower promise: `tokens --write` only ever **adds** a declaration that is missing,
never reads or rewrites one already there.

**Generalise it as a question to ask of any tool with a refuses-to-touch rule:** what class of change
crosses the line it will not cross, and does anything at all report it? Here the answer was nothing,
for three releases, and the failure surfaced two commands downstream as a deck's own defect.

Related: [L-77](L-77.md) on a sync writing over a generated file, the other edge of the same
command; [L-05](L-05.md) on a check only ever seen passing — the fixture this task owed was a deck
one release behind in a token, and before the fix the tool called it clean.
