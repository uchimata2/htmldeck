# L-158 — A rule no tool asks for is back-filled, not fixed, and the record of back-filling it is the evidence that it recurs

Found 2026-09-02 in [T-238](../../tasks/T-238-the-trackers-own-rules-against-its-own-records.md),
closing `PR-27`. [`TASK-WORKFLOW.md`](../../tasks/TASK-WORKFLOW.md) §3 says `shipped_in` is set at a
task's close. Nothing checked it: the field is a **carried** one in
[`.taskmd/config.md`](../../.taskmd/config.md), deliberately outside the schema's vocabularies
because its values are version strings, so `taskmd check` validated every enumerated field and never
this one. [`RELEASE-HISTORY.md`](../RELEASE-HISTORY.md) §1 records the defect twice before the audit
found it a third time — eight records in one release, one in the next. The audit named two. On the
day it was fixed there were **44**.

- **The project had already diagnosed it, twice, in writing.** Both earlier recurrences were noticed,
  understood, corrected and documented — and the correction was the same each time, so the third one
  was scheduled the moment the second was closed. Writing a recurrence down is not a fix; it is a
  record that the fix has not been made yet.
- **A field outside a validator's vocabulary is outside its attention entirely.** The exclusion was
  right — no enumeration can hold a version string — but *not enumerable* was silently read as *not
  checkable*, and the two are unrelated. **Presence** is checkable for any field whatever its values
  are, and presence was the whole rule.
- **The count between recurrences is the measure of the gap, not the size of the mess.** Two, then
  eight, then 44: the interval got longer, so the population got larger, so each back-fill looked
  more like real work and less like the same omission. The work is what disguises it.
- **Where a rule says *at close*, the check belongs in what a close runs.** `lint.py` is the closing
  checklist's command, so the check is its fifth step; putting it in the release gate would report at
  the next release, which is the delay that produced eight in one batch. [L-157](L-157.md) is the
  sibling case — there the proof existed and covered half the step; here there was no proof at all.
