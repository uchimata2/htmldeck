# L-119 — Pairing two independent measurements by position turns a rare dropped sample into a false verdict

A rule that compares two runs of the same measurement has to say **which reading pairs with which**.
The obvious code pairs them by position — `zip(a, b)` — and that is correct exactly as long as both
runs produce every sample. The moment one run drops a sample, position stops meaning identity:
sample *n* is compared against sample *n+1*, and every pair after the gap is wrong.

**The damage is not proportional to the gap.** One missing sample out of four does not cost a
quarter of the accuracy; it invents a disagreement the size of the distance between two different
subjects. Measured 2026-08-18 on a real four-slide sample:

| | values compared | worst non-text | worst text run |
| :--- | ---: | ---: | ---: |
| both runs intact | 120 | 0.00 du | 1.70 du = 1.00 device px |
| one reading dropped | 64 | **314.14 du** | **816.41 du = 479.26 device px** |

The bound was 0.25 du and 2.0 device px. So a deck with a *perfect* score reports a failure roughly
three orders of magnitude outside tolerance — and the tolerance is the first thing anyone suspects,
which is the wrong place to look and the expensive one.

**The symptom is worse than a wrong answer: it is an intermittent one.** The upstream drop is rare —
0 in 30 direct reads and 0 in 72 more, under light load — so the gate is green almost always and red
occasionally, on a tree nothing touched. Re-running clears it. That teaches the reader that a red run
means *run it again*, which is the habit that makes a real regression invisible, and it costs the
whole gate its authority rather than one rule's.

**The fix is not to make the upstream reliable.** It cannot be: it is a browser, under load, and the
drop rate is a property of the machine. The fix is that the comparison **pairs by identity** — each
reading already carried the name of the slide it measured, and nothing read it — and that a run whose
two halves measured different sets reports **undecided, not failed**. Undecided is the honest verdict:
failing repeats the misalignment's wrong answer, and passing hides a run that measured nothing it
claims to have measured.

**How to apply.** Wherever two collections of measurements are compared:

1. **Pair on the identifier, never on the index**, and check the identifier is present on both sides.
   If the readings carry no identifier, that is the first defect — add one before writing the
   comparison.
2. **Treat unequal lengths as a fault of the run**, reported in its own terms, not as fewer
   comparisons. Silent truncation is what `zip` does by design, and it is the wrong default here.
3. **Check for repeats too.** A probe that fails to advance measures one subject twice; that pairs
   cleanly by name and still measures half of what it claims, so the duplicate is its own check.
4. **A sampler that drops a sample must not `continue` quietly.** Where it does, the consumer is the
   only place the loss can still be caught.

The general shape: **an aggregate over misaligned pairs is not a degraded measurement, it is a
measurement of something else.** `counted` fell from 120 to 64 in the case above, and that number was
sitting in the output the whole time with nothing comparing it to what it should have been. Related:
**L-110** — the instrument that fails silently — and **L-36**, since an intermittently-red gate and a
never-firing check corrode trust from opposite directions.
